# Filletry — Integrations

## 1. Print agent (`agent/print-agent/`)

A small Node service a tenant runs on any always-on machine on the plant LAN (Windows
PC, Raspberry Pi). It replaces the Odoo IoT box.

- Pairs with the org via a one-time code from Admin → Devices → Print Agents; stores a
  scoped token (RLS role `agent`, limited to `print_job`, `printer`, `scale_reading` of
  its org).
- Subscribes (Supabase Realtime) to `print_job` where `printer.agent_id = me and
  state = queued`; claims a job (`queued → printing` with `for update skip locked`),
  sends:
  - `zpl` → raw TCP to `host:9100` (Zebra ZD421/ZP-450). No driver. (CUPS/driver
    installs are a known cause of gibberish output — don't.)
  - `pdf_url` → downloads and prints via OS (`lp` on Linux/macOS, `SumatraPDF -print-to`
    or PowerShell on Windows) to the configured printer name.
- Marks `done | failed(error)`; retries 3× with backoff; heartbeats `last_seen_at`
  every 30 s (Admin shows offline agents — a dropped LAN box looks like "printing
  randomly broken").
- Optional **scale** module: reads a Mettler Toledo BC60 / Toledo 8217 serial stream
  (`/dev/ttyACM0` or `COMx`, 9600 8N1 — settings per scale record), parses weight +
  stable flag, debounces, inserts `scale_reading` rows (rate-limited to changes), which
  the reconcile screen consumes via Realtime.
- Ships as a single binary (`pkg`/`bun build`) plus a `.service`/Task Scheduler
  snippet. Logs to file; never logs tokens.

## 2. Labels (`packages/labels/`)

- **Tote tag** (4×6 ZPL): intake number ≥ 100 pt, QR `FL:TOTE`, species/lb lines with
  shorthand, customer name, date, "Tote X of Y", banners FAST PASS / DIRTY / RIBBING /
  SMOKED EXCHANGE.
- **Storage box label**, **box/pick label**, **location tag** (one tag per shelf
  position showing both depths: **R on top, F on bottom**, mirroring the shelf),
  **asset tag sheet** (3-digit codes, Code-128 + QR).
- **Receipts** (HTML → PDF via Playwright/Chromium in a Route Handler, or react-pdf):
  intake receipt (lines, rates, est. pickup, status-page QR, rates notice), pickup
  receipt (card last4/brand/entry/auth), angler settlement receipt (boxing QR), storage
  receipt.
- Every QR is generated by `packages/rules/qr.encode` and every parser uses
  `qr.parse` — a label template never hand-builds QR text. CI has a round-trip test
  per label kind.

## 3. Scanners
Bluetooth or USB keyboard-wedge scanners (Zebra CS60 / Socket S720 in HID mode). No
app pairing; `<ScanInput>` captures them. Camera scanning is a later enhancement.

## 4. Shipping — Shippo (`packages/shipping/`)
Address validate, rates (carrier allowlist per org, `*` = all; Rate Check bypasses),
buy label (one `transaction` per parcel — multi-parcel must fetch **every** label),
tracking webhook → `shipment.state`. Retry rate calls when the live-carrier set comes
back **thin, not just empty** (carrier APIs lag). Cold-chain note: packaging + dry-ice
weight added per box size.

Route handlers (Next.js, Node runtime) — the only shipping code that uses the service role,
which it uses to read the org's Shippo key from Vault (`shippo_api_key:<org id>`) and to record
provider results (`shipping_record_*`, `shipping_buy_failed`, `shipping_apply_tracking`); reads
and the buy claim run as the caller:
`POST /api/shipping/{verify,rates,buy,rate-check}` and `POST /api/shipping/webhook?token=…`
(Shippo `track_updated`; `SHIPPO_WEBHOOK_TOKEN`). See `docs/wp/WP-19.md`.

## 5. Stripe Billing (tenant subscriptions)
Checkout + Customer Portal; webhook updates `org.plan`; feature gates read `org.plan`.
Five tiers $79–$899 (names/limits: DECISION-06).

## 6. Email / SMS
Transactional email via Resend (intake confirmation, ready-for-pickup, shipped).
SMS deferred (DECISION-08).

## 7. Status page
Public route with per-org rate limit (Vercel KV or Supabase function). No auth.
