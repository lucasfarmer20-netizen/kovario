## Derived values (never app-maintained)

| Value | Mechanism |
|---|---|
| `intake.total_incoming_lb`, `total_est_yield_lb`, `ribbing` | BEFORE trigger on `intake` recomputes from lines on every write; line writes touch the intake |
| `intake.hold_until` | defaults to `intake_at + org.settings.hold_hours` |
| `intake_line.ribbing`, `est_yield_lb`; `charge.amount`; `register_order_line.amount` | generated columns |
| `storage_intake.box_count`, `active_box_count` | same pattern as intake totals |
| `vessel.location_id` | AFTER INSERT trigger on `location_placement` mirrors the latest placement |
| `storage_box.days_stored` | view `storage_box_days` → `app.storage_days()` in org tz |
| reconcile `variance_pct` | view `reconcile_variance` |
| `allocation_session.fulfillment_status` | view `allocation_session_fulfillment` |
| transition timestamps (`pulled_at`, `stored_at`, `released_at`, `emptied_at`, …) | stamped by the guard trigger on entering the state |

## State transitions

`supabase/seed/state_transitions.sql` is generated by WP-04 (`pnpm --filter rules gen:states`)
and is loaded by `supabase db reset` (`[db.seed] sql_paths` in `supabase/config.toml`).
**Deployed environments must apply it after migrations**, e.g.
`psql "$DATABASE_URL" -f supabase/seed/state_transitions.sql` (it is idempotent). Without
it the guard fails closed: every state change is rejected.

## Automated checks

```bash
supabase start && supabase db reset
pnpm test:db
```

`supabase/tests/05_domain_schema.test.sql`:
- catalog: every domain table exists, has `pg_policies` policies and the org-scoped SELECT
  policy, maintains `updated_at`, and is not client-writable; views are `security_invoker`
  and closed to `anon`; enums are named `<table>_<col>`; every entity in the seed has a
  guarded table;
- denormals: intake totals/ribbing across line insert/update/delete and a direct write;
  `charge.amount`; storage box counts; `storage_box_days` and S4 day counting; vessel
  location mirror; `reconcile_variance`; fulfillment rollup none → pending → partial →
  released;
- guard: `draft → stored` rejected; `holding → processing` stamps `pulled_at`; box plans
  never roll back; `force_transition` is manager-only, needs a reason, stays in the caller's
  org, writes `action_log`, replays, and leaves no bypass behind.

`00_tenancy_isolation.test.sql` (WP-02) now also sweeps every new table.
