## Verify

1. `supabase start && supabase db reset --no-seed && supabase test db supabase/tests/07_reference_data.test.sql`
   passes. Then `delete from app.state_transitions;` in psql and re-run: it fails.
2. Stub-run the deploy script (prints the CLI calls, writes nothing):
   ```bash
   stub=$(mktemp -d); printf '#!/usr/bin/env bash\necho "supabase $*"\n' > $stub/supabase; chmod +x $stub/supabase
   PATH="$stub:$PATH" SUPABASE_ACCESS_TOKEN=x SUPABASE_PROJECT_REF=abcdefghijklmnopqrst \
     SUPABASE_DB_PASSWORD=x SITE_URL=https://app.filletry.com bash scripts/deploy-supabase.sh production
   ```
   `git status` shows `supabase/config.toml` unchanged (the hosted auth URLs go into a temp copy).
3. `actionlint` reports no errors for both workflows.
4. On a PR from this repository, job `migrations-dry-run` lists the migrations staging would
   apply. After merge, Actions → Deploy → `staging` shows `db push` and `functions deploy`,
   and the Supabase dashboard's migration list matches `supabase/migrations`.
5. Actions → Deploy → Run workflow with a staged `sha`: `promote-check` passes the staging
   check, then skips prod while the `production` environment does not exist.
6. Against a local stack, run `pnpm db:preview-demo` twice (`STAGING_SUPABASE_URL` = local API
   URL): one `preview-demo` org, two sites, one owner membership.
