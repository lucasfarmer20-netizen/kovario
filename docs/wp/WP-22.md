## Plans and gates (DECISION-06 default — placeholders)

| Plan | $/month | Sites | Station devices | Users | SMS |
|---|---|---|---|---|---|
| starter | 79 | 1 | 3 | 5 | – |
| plant | 199 | 1 | 8 | 15 | – |
| plant-plus | 349 | 2 | 15 | 30 | ✓ |
| multi-site | 599 | 5 | 40 | 75 | ✓ |
| enterprise | 899 | ∞ | ∞ | ∞ | ✓ |
| *(no subscription)* | – | 1 | 1 | 2 | – |

DECISION-06 names the tiers and the gated things but not the numbers; they live in one table
(`PLANS` in `packages/payments/src/billing.ts`). Gates only block **adding** (an org above its
limit after a downgrade keeps what it has). `org.plan` is written only by the webhook
(`billing_apply_subscription`) — and by the demo seed script, which makes `demo-plant`
`enterprise` so e2e is never gated.

## Stripe setup (per environment)

1. In Stripe, create one recurring monthly Price per plan with **lookup key**
   `filletry-<plan>` (e.g. `filletry-plant-plus`). Checkout resolves prices by lookup key,
   so no price ids are configured anywhere.
2. Enable the Customer Portal (plan switching between those prices, cancel, card update).
3. Webhook endpoint `https://<project>.functions.supabase.co/billing-webhook` with events
   `customer.subscription.created`, `customer.subscription.updated`,
   `customer.subscription.deleted`.
4. `supabase secrets set STRIPE_SECRET_KEY=… STRIPE_WEBHOOK_SECRET=…` (Edge Function secrets;
   never in the repo). Without them the billing functions answer `503 billing_not_configured`
   and `/admin/subscription` says so.

Webhook safety: signature + 5-minute timestamp tolerance; one `billing_event` row per Stripe
event id (redelivery is a no-op); an event older than the one that last set the plan is
recorded but not applied (out-of-order delivery); a cancelled *superseded* subscription never
clears the current plan; an unparseable `metadata.org_id` is ignored instead of failing (which
would make Stripe retry forever).

## Automated checks

```bash
supabase start && supabase db reset
pnpm -r test          # payments billing + stripe-billing, rules reference-seed, web lib/*
pnpm test:db          # 22_onboarding_billing.test.sql + db suites below
```

- `supabase/tests/22_onboarding_billing.test.sql` — create_org: anon / station refused,
  validation (slug, timezone, payload, taken slug), everything created in one transaction
  (owner + default membership, previous default unset, refreshed token stamps the new org,
  site, seed counts, default rate-card keys at $0, action_log, `org_created`), replay returns
  the stored result, another user cannot reuse the id; re-seed inserts nothing; settings
  validation (ranges, tolerance ≤ target, tax mode/rate, allowlist, money rates rejected as
  settings); rate cards (copy, overlap → 23P01, undated default, virtual `fresh` has no rate,
  negative/duplicate keys, default/used cards not deletable); species/method toggles;
  cross-org; billing writes are service-role only, link-customer race, unknown customer,
  apply/duplicate/stale/other-subscription/cancel, `org_plan_changed` events, org hint.
- `packages/db/src/onboarding.db.test.ts` — a brand-new account (no org claims) creates an
  org with the **real** processing-rules payload through PostgREST, replays the same id, then
  after `refreshSession()` is owner of the new org with 17 species, 250 yields and a default
  card holding every service method + named rate.
- `packages/db/src/billing.db.test.ts` — served Edge Functions: checkout/portal need an owner
  (401/403), reject bad plan/return URL, and the webhook rejects unsigned/forged events
  without touching `org.plan`.
- `packages/db/src/seed-demo-org.db.test.ts` — `demo-plant` has an intake in **every**
  `intake_state`, tags in use are bound to occupied vessels, the stored vessel has a location,
  every intake past draft has all X-of-Y tote tags, and a second run changes nothing.
- `packages/payments/src/billing.test.ts` / `stripe-billing.test.ts` — catalogue, gates,
  lookup keys, parity of the edge copy with the catalogue, signature (valid / tampered /
  wrong secret / replay window), event → plan for every status, request shapes against a
  fake `fetch`, Stripe errors never echo the key.
- `apps/web/lib/plan.test.ts` (`requirePlan`), `org-settings.test.ts`, `rate-card.test.ts`,
  `onboarding.test.ts`, `billing.test.ts`.

## Manual check (local)

1. `node scripts/web-env.mjs`, `pnpm dev`, open `/signup`, create an account (local auth
   needs no email confirmation; in production the link lands on `/onboarding`).
2. `/onboarding`: name the plant → you land on **Rates** as owner (17 species and 250 yields
   are in `/admin/species`); enter rates, **First station** adds one device; a second one is
   refused with “Without a subscription, Filletry allows 1 station device…”.
3. **Plan** / `/admin/subscription`: with Stripe test keys set as function secrets and the
   prices from “Stripe setup”, **Choose** opens Checkout; pay with `4242 4242 4242 4242`; after
   the webhook the page shows the plan and **Manage billing** opens the Customer Portal.
   Locally, forward events with `stripe listen --forward-to
   http://127.0.0.1:<api-port>/functions/v1/billing-webhook`; give the local edge runtime the
   printed signing secret and your test key under `[edge_runtime.secrets]` in
   `supabase/config.toml` (local edit, never committed) and restart the stack.
4. `pnpm db:seed-demo` (after `supabase db reset`), then `pnpm db:demo-owner` and sign in:
   `demo-plant` shows customers, a lodge, rates and intakes `INT-0002…0010` in every state (`INT-0001` is the WP-05 station gallery fixture from `supabase/seed.sql`).
