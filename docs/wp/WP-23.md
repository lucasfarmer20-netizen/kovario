# WP-23 — End-to-end smoke suite over the demo tenant

Playwright (`@playwright/test` 1.58.2, the same Playwright the labels package already pins)
drives the real app against the local Supabase stack and the demo tenant `demo-plant`
(`supabase/seed.sql` + `pnpm db:seed-demo`). Two flows, each one test with a `test.step` per
station so a failure names the station:

| Flow | Spec | Steps |
|---|---|---|
| Sport intake to pickup | `apps/web/e2e/sport-intake.spec.ts` | intake (new customer, line, 2 totes, Save & Print) → wave (both totes verified by scan, complete) → rollstock (tote scan opens, Finish queue) → reconcile (tote scan, tag scan binds a vessel, manual weight, Send to Blast) → blast (tag scan) → locate (tag scan, location scan) → status page "Ready for pickup" → allocation (pool, angler, will-call box, Save & Price) → boxing (box tick, basket ticked by tag scan, Complete closes the intake) → register (Load outstanding, cash via the `manual` provider) → status page no longer lists it; intake timeline shows "Picked up" |
| Storage intake to release | `apps/web/e2e/storage-intake.spec.ts` | storage intake (customer, location, two boxes, Confirm) → pickup batch for Box 1 → register (batch loads as outstanding, cash) → batch Released with its payment ref, Box 1 picked up, Box 2 still stored, intake "Partly picked up" |

## Pieces

| Deliverable | Where |
|---|---|
| Specs | `apps/web/e2e/sport-intake.spec.ts`, `apps/web/e2e/storage-intake.spec.ts` |
| Scanner emulation helper (types QR text + Enter into the focused `<ScanInput>`; QR text from `rules` `encode`) | `apps/web/e2e/scanner.ts` |
| Demo tenant + signed-in owner (runs `pnpm db:seed-demo`, creates the e2e owner with `scripts/demo-owner.mjs` and a random per-run password that is never written or logged, signs in through `/login`) | `apps/web/e2e/global-setup.ts`, `apps/web/e2e/demo.ts` |
| Shared station steps (customer search/create, free asset tag from `/admin/asset-tags`, cash at the register, anonymous status page) | `apps/web/e2e/stations.ts` |
| Config (`next start` in CI, `next dev` locally, serial: one plant floor) | `apps/web/playwright.config.ts` |
| CI job | `.github/workflows/ci.yml` `check`: `node scripts/web-env.mjs` before `pnpm build` (NEXT_PUBLIC_* are inlined at build), then `pnpm e2e`; the report and traces upload on failure |
| Demo box sizes (allocation needs one to plan a box) | `scripts/seed-demo-org.ts` |

Each run makes its own customer (random `907-555-xxxx` number) and takes a free asset tag, so
the suite re-runs on a reused local stack; the boxing release frees the tag again.

## Run it locally

```bash
supabase start && supabase db reset
node scripts/web-env.mjs
pnpm e2e                      # starts `next dev` on :3100 (or reuses one), seeds, signs in, runs
CI=1 pnpm e2e                 # what CI runs: serves the production build (`pnpm build` first)
```

## Bugs the smoke found (fixed here; both were invisible to mocked unit tests)

- **Reconcile and blast could not list vessels.** `vessel` ↔ `asset_tag` have foreign keys both
  ways (`vessel.asset_tag_id`, `asset_tag.current_vessel_id`), so PostgREST refused the
  `asset_tag(code)` embed (PGRST201). Reconcile showed "Refresh unavailable" and never showed a
  bound vessel, so nothing could be weighed or sent to blast. The embeds now name the FK
  (`asset_tag!vessel_asset_tag_id_fkey(code)`); the response shape is unchanged.
- **Every register payment from the browser was refused with "Sign in first".** The register
  sends its access token as a bearer header; `/api/payments/*` built a bearer client and called
  `auth.getClaims()` without the token, which reads the (empty) client session. It now verifies
  the token it was given, as `lib/shipping/http.ts` already did. Regression test:
  `lib/payments/service.db.test.ts` "a register's bearer token is a signed-in caller".

## Doc vs issue

The issue asks for the status page to show "Picked up". `docs/04-BUSINESS-RULES.md §13` (and
WP-20) show only **open** intakes, and a picked-up intake is `done`, so the doc wins: the smoke
asserts "Ready for pickup" while the fish is stored, that the intake drops off the status page
after pickup, and "Picked up" on the staff intake timeline.

## Not covered (hardware / manual)

- **Real scanner hardware.** The helper types exactly what a keyboard-wedge scanner types into
  the focused input. To verify a physical scanner: open `/reconcile` on the station, scan a
  printed tote tag and an asset tag, and see the intake open and the vessel row appear.
- **Boxing QR from the printed receipt.** The receipt renders the `FL:BOX:` token only as an
  image, so the smoke opens the party from the boxing queue (the other entry docs/06 allows);
  `FL:BOX` encode/parse round-trips are unit-tested in `packages/rules/src/qr.test.ts`. By hand: print a
  settlement receipt, scan its QR at `/boxing`, and see that party open.
- **Printers, scales and card terminals.** The demo has no printer, scale or terminal; the flows
  use manual weight entry and the `manual` (cash) provider. Card terminals are covered by the
  WP-17 fake SPIn server tests.
- **Paired station devices and operator PINs.** The smoke signs in as the demo owner (stations
  accept a staff session, which needs no operator PIN). Pairing and PINs are covered by
  `supabase/tests/04_devices_pins.test.sql` and `apps/web/lib/pairing.test.ts`.
