## Release modes

| Mode | Caller | Ref | Charge |
|---|---|---|---|
| `payment` | WP-16 paid hook via `app.release_pickup_batches` | terminal ref / register order number (never empty) | settled by the payment |
| `manual` | manager Force Release | given ref, else the payment already stamped on the batch, else `MANUAL` | settled if a payment is recorded; otherwise stays `open` (a later payment is **adopted**, S7) |
| `comp` | manager COMP | `COMP` | `comped` with the reason; waived amount in the note |

Anomalies append a batch note (append-only, enforced by trigger) and, for
warning/error/critical, write a `storage_batch_alert` domain event and a server log line.

## Manual walkthrough

1. `supabase start && supabase db reset`, `node scripts/web-env.mjs`, `pnpm db:demo-owner`,
   `pnpm db:seed-demo`; give the demo owner a PIN in **Admin → Users**. Make sure the rate
   card has `storage_per_box_day`.
2. For labels/receipts, add printers at the site with `is_default_for` `{"storage_label": true}`
   / `{"receipt": true}` (or bind them to the device). Without one, confirm still succeeds and
   says no printer is set up.
3. `/storage`: pick a customer, a location, add boxes (weight, description) →
   **Confirm & Print Labels** → `/storage/<id>` with the STG number, boxes and days stored.
4. Tick boxes → the quote shows days × rate per box and the total → **Create Pickup Batch**
   → a pending `SPB-` batch (charge it at the register once WP-16 lands). Creating another
   batch over the same boxes replaces it.
5. **Force Release** or **COMP** on a batch → reason → manager PIN. **Receipt** shows the
   same day counts as the box table. `/storage/queue` lists stored / partly picked up intakes
   with box rollups and pending pickups.
