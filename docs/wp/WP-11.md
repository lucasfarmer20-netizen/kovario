Hardware-only check (Bluetooth keyboard-wedge scanner and floor tablet):

1. Pair a rollstock device, open `/rollstock`, and identify with an operator PIN.
2. Scan a numbered tote. Check green flash, short beep, OPEN number, species,
   notes badges, and tote count. Scan another tote of that intake, then the next
   intake: the previous order should advance without touching the tablet.
3. Try an unknown label and try advancing with a missing tote. Check red flash,
   rejection sound/vibration, readable reason, and unchanged OPEN intake.
4. Finish the final intake with **Finish queue**. For a missing tote, enter a
   manager override reason and PIN; check the audit event and reconcile queue.
5. Confirm the scanner still captures Enter-terminated scans after PIN overlays,
   rejected scans, and tapping Finish queue, using wet gloves. Check the sound
   unlocks on the first user gesture and the tablet's volume/vibration settings.

No dependency stubs or decision changes. DECISION-20 is preserved: holding bypass
first transitions to processing, writes `rollstock.holding_bypass` on the intake's
domain-event history, then opens rollstock. Manager overrides use the existing
`elevate` Edge Function and append `rollstock.completeness_override` with reason,
manager, scanned and expected counts. An override finishes the current order;
the next tote can then open normally.
