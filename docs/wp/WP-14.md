## The penny rule

`price_session` splits the session's pooled processing charges across its anglers:

1. Work in whole cents; weights are take-home lb in hundredths (`weight`) or 1 each (`even`).
2. Each angler gets the floor of `total × wᵢ / Σw` cents.
3. The leftover cents (fewer than the number of anglers) go one each to the largest
   remainders; a tie goes to the earlier angler (lower `STL-` number).

Shares therefore always sum to the pooled charges exactly. A weight split where every angler
has 0 lb is refused ("enter lb or split evenly"). The TS rule and the generated SQL agree on a
seeded grid (`allocation.db.test.ts`).

## Pricing

- **Pool** = the open `processing` + `ribbing` charges of the pooled intakes (voided, comped,
  settled and non-processing charges excluded).
- **Box fees** = Σ catalogue fee of the angler's box plans. **Freight** = placeholder, carried
  as stored (0 until WP-19 quotes shipping). **Total** = share + box fees + freight.
- `price_session` moves `draft → priced`. Any save on a priced session reprices it in the same
  transaction, so stored numbers are never stale. A session with a paid settlement, or a
  done/cancelled one, cannot be edited, repriced or cancelled; released boxes cannot change or
  be removed.

### Assumption (not in the docs): an intake pooled in two sessions is billed once

`docs/02 §8` allows an intake in several sessions (m2m) but does not say how its charges are
priced twice. Splitting the full charges in each session would double-bill the customer, so
**the earliest non-cancelled session pooling an intake bills its charges**; other sessions show
"Billed by ALC-…" for that intake and split only what they bill. Cancelling the billing session
hands the intake to the next session, which is repriced at once. This is
`app.intake_billing_session`; if the plant wants a different rule (e.g. apportion by lb across
sessions) it is one function to change. Flagged in the PR for confirmation.

## Manual walkthrough (done locally against the demo org)

1. `supabase start && supabase db reset`, `node scripts/web-env.mjs`, `pnpm db:demo-owner`,
   `pnpm db:seed-demo`, `pnpm dev`, sign in. (Demo intakes have no charges; add some or save
   real intakes at `/intake` to see non-zero processing shares.)
2. **Admin → Box sizes**: add e.g. Medium 50 lb $12.50, Large 90 lb $15.
3. `/allocate/new`: find the party → tick their open intakes → **Start session**. Add more
   intakes by number or by scanning a tote tag. Enter each angler's species / method / lb, add
   boxes (method, size, weight). A box over 70 lb shows **Heavy OK**; saving without it is
   refused.
4. **Save & Price** → `/allocate/<id>`: pooled processing, per-angler settlements, **Receipt**
   (browser print, boxing QR) and **Print** (queues the receipt job). Hand off to the register.
5. `/allocate` lists sessions with state / fulfillment filters and search; scanning a receipt's
   QR opens its session.

## Stubs and notes

- **Receipt print job**: like the WP-07 intake receipt, `print_settlement_receipt` queues a
  `receipt` job whose `source` names the template (`settlement_receipt`) and carries the
  `FL:BOX:<token>` QR; the PDF render/upload step is the print pipeline's (the agent prints PDFs
  only from an HTTPS URL, and no render/upload exists yet — see WP-09's note). The station's
  receipt page prints the same receipt from the browser today.
- **Freight** is a placeholder (stored `freight_total`, 0) until WP-19.
- **Payment** of settlements and settling the billed charges (`app.session_billed_charges`) is
  WP-16; **release** (box/vessel ticks, I1–I17, `done`) is WP-15.
- Counter allocation is a tablet/keyboard station: station styling, no `<StationShell>` scan
  focus (same as intake/storage).
