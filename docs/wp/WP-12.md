## Hardware-only verification

No physical scale or captured plant frames were available in this workspace. Parser tests
use explicit protocol fixtures, not claimed hardware captures. Before plant rollout:

1. Configure a scale record with the paired print agent, `protocol=toledo_8217`, and its
   serial `port` (COMx on Windows or /dev/ttyACM0 on Linux). Bind that scale's id to the
   reconcile device's `scale_id`. Use Toledo W-response mode, **lb**, 9600 8N1. Other
   serial modes and units are deliberately rejected/unsupported in this module.
2. Run the built print agent on the target operating system. Confirm serial access and
   poll replies. Record sanitized weight/status byte frames from the physical Toledo
   8217 / BC60; add them to the parser fixtures before declaring that model qualified.
3. Place a known weight; shake the platform, then let it settle. Verify only stable,
   debounced changes reach `scale_reading`, and the reconcile widget updates without
   reload. Accept onto the highlighted vessel; compare weight and provenance.
4. Scan 42 / 042 / 0042 while two reconcile screens are open. The second screen must
   name the holding intake. Remove the first row; the second screen can then bind it.
5. Print the active tag sheet from `/admin/asset-tags` to a configured ZPL printer.
   Check the 3-digit text and scan both Code-128 and QR back into reconcile.
6. Enter manual mode, type and save a weight, then scan another tag. Confirm scan focus
   returns and the saved weight displays `(manual)`.

## Interfaces and defaults

- `bind_tag` takes a canonical or padded numeric code and an intake id, and creates the
  occupied vessel while reserving the tag in one transaction. Reconcile does not create
  an unbound vessel in a separate round trip. `send_to_blast` is a transactional wrapper.
- Station scans parse through `rules/qr.ts`, use the shared IndexedDB queue, and audit
  accepted/rejected results in the domain transaction. Direct edits carry action ids.
- No dependency stubs. Existing station sessions, print queue, label renderer, domain
  tables and rules are reused. No decision default changed; DECISION-04 online with
  queued scans and DECISION-11 lb apply.
- Variance uses stored per-line estimates and sums occupied vessels for the intake.
  This work package does not add a vessel-to-species allocation workflow.

Protocol reference: [Mettler Toledo BC service manual, Toledo host commands](https://www.mt.com/dam/ind/IND_PDF/30126862_R02_BC_Scale_SM_EN.pdf). The agent polls W; this is not the distinct Toledo continuous-output protocol.
