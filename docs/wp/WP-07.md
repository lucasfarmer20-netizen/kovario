## How a save works

1. The station builds lines with the matrix-filtered dropdowns (`allowedConditions` /
   `allowedMethods` from packages/rules, limited to the org's active species, conditions and
   methods). The price panel is `buildIntakeDraft(lines, intake_price_context)`.
2. **Save & Print Tote Tags** sends `savePayload(...)` — lines with the yield snapshot and the
   charge drafts (kind, line, rate key, qty), **never a price** — to
   `save_intake(client_action_id, payload)` through `withAction`.
3. In one transaction `save_intake` locks the customer, assigns the `INT-` number (skipping any
   number already taken outside `next_seq`), snapshots the active rate card and the lodge flag,
   writes the lines, checks the drafts are the rules engine's expansion of the lines, prices
   each draft with `app.price_per_lb` from the snapshotted card, writes tote tags
   (`FL:TOTE:<INT-…>:<n>`), sets `locked`, moves `draft → holding`, and queues one
   `print_job(tote_tag)` per tote (+ a `receipt` job when asked).
4. A replay of the same `client_action_id` returns the stored result.

**Read-only:** clients cannot write intake tables; `save_intake` refuses a locked intake, and a
trigger rejects line writes on a locked intake even from definer code.
**Unlock:** `unlock_intake` needs an owner/manager session or a live manager elevation (manager
PIN → `elevate` Edge Function); only `draft`/`holding` intakes; writes `action_log`
(`intake.unlock`, with the approving manager and reason). **Re-save** voids the intake's open
charges and re-creates them; settled/comped charges are kept and their drafts not re-created.
The rate card stays the original snapshot; the lodge flag is re-read.

**Reprice:** `set_lodge_guest` (WP-06) writes `customer_lodge_flag_changed`; an insert trigger
runs `app.reprice_customer_open_charges(customer)` in the same transaction and marks the event
processed. Only open, unpaid **processing** charges on **non-Fast-Pass** intakes are repriced
(from each intake's own rate card); ribbing and Fast Pass are never touched.

## Manual walkthrough

1. `supabase start && supabase db reset`, `node scripts/web-env.mjs`, `pnpm db:demo-owner`,
   then give the demo owner a PIN in **Admin → Users**, and set rates in **Admin → Rate cards**
   (`pnpm db:seed-demo` fills reference data and rates, but currently stops at its intake
   fixtures because `supabase/seed.sql` already inserts `INT-0001`; the reference data and
   rates it wrote are enough).
2. For tote/receipt jobs, add printers at the site with `is_default_for` `{"tote_tag": true}` /
   `{"receipt": true}` (or bind them to the station device). Without one the save still
   succeeds and the header says no printer is set up.
3. `pnpm dev`, sign in, open `/intake`. Type 3+ digits of a phone → pick a customer (or
   "New customer…").
4. Line 1: Silvers → Whole → Fresh, 50 lb, fillets 60. Line 2: Halibut → Filleted (ribs in)
   (method becomes Portions), 30 lb. The panel shows four charges with per-lb rates, est. yield
   per line and the total. Toggle **Fast Pass**: processing rates rise to the floor, ribbing
   stays.
5. **Save & Print Tote Tags** → `/intake/<id>`: big intake number, Locked badge, hours in
   cooler, Reprint / Print Receipt / New Intake / Unlock; lines, charges, tote tags, timeline.
6. **Unlock** → manager PIN → the form opens with the saved lines; change a weight and save →
   locked again, charges re-created (`charge.state = voided` on the replaced ones).
7. `/intakes` lists intakes newest first with state and the "Nh in cooler" badge.

## Stubs and notes

- **Print transport and rendering are WP-08.** A `print_job` here is a row: `payload` is empty
  and `source` carries `{template, intake_id, intake_number, tote_tag_id, tote_no, of_count,
  qr}` (receipt: `{template: 'intake_receipt', intake_id, intake_number}`) for WP-08 to render.
  Printer routing (`app.station_printer`) reads the device's own printer, then a site printer
  whose `is_default_for` names the job kind; never an org-wide default.
- Intake is a keyboard station: it uses the station styling but not `<StationShell>`, whose
  always-focused scan input would take the keyboard away from the form.
