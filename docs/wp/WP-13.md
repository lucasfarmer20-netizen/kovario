## How to verify by hand (scanner hardware)

1. In `/admin/locations`, generate zone `IF` with rows `A 2 2` and both depths. Generate
   again: the message says nothing new was added. Add a pallet: it becomes `IF-PALLET-01`.
2. Print the `IF` tag sheet to a ZPL printer. Shelf labels show R above F. Scan each QR
   into a text field: it reads `FL:LOC:<org-slug>:<code>`.
3. Send an intake to blast at `/reconcile`. At `/freezer/blast`, scan a vessel tag. The
   tag appears under IN BLAST with its time in.
4. At `/freezer/locate`, scan the same tag (STEP 2 shows the intake), then a shelf label.
   You should get a green "Placed …" and a reset to STEP 1. The intake is now `stored`,
   and the vessel has left the blast list.
5. Archive a location in admin, then try to place a vessel on it. You should get a red
   "archived and cannot be bound". The vessel stays pending for another location.

## Interfaces, defaults and scope notes

- SQL never parses QR text. Scans are matched against master `qr` text, or against a
  canonical code (bare tag `42`/`042`, bare location code). Codes and QR text come from
  `packages/rules` (`locations.ts`, `qr.ts`). The `location_code_shape` constraint is
  generated by `renderLocationShapeSql()`, and a test pins it to its migration.
- `locate_scan` wraps the two-step loop in one idempotent scan action, as rollstock
  does. A location scan places the pending vessel. Anything else is read as a vessel tag.
- `sort_key` was rebuilt with fixed-width fields under the `"C"` collation. The previous
  key compared variable-width rows and zones in the database's default collation, so
  `AA` could walk before `A`. Numeric rows are padded to two digits (`1` → `01`) by the
  generator.
- Archiving a location with baskets on it is allowed. The baskets stay put; the reply
  counts them so the crew can relocate them. Only new bindings are refused
  (DECISION-14/15: never strand baskets).
- `location_placement.placed_at` is stamped with `clock_timestamp()`. The mirror trigger
  then picks the latest placement correctly, even within one transaction.
- Untagged smoked-exchange vessels cannot be scanned, so they cannot be placed at Locate.
  No doc defines a scan identity for them. They appear in `vessel_walk_order` with no
  location.
- The boxing pick list UI itself is WP-15. This package delivers the `vessel_walk_order`
  view that the pick list reads.
- No dependency stubs. No `DECISION NEEDED` default was changed. DECISION-04 applies
  (online, with the queued IndexedDB scan queue), as do DECISION-14 and DECISION-15.
